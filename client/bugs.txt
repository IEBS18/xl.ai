# Bug Analysis and Fix Plan

## Bug 1: Processing Status Persistence After File Upload
**Issue**: `isFileProcessing` shows "processing" even when `assistant_upload_status` is "completed" after page refresh/direct navigation to `/chat/session-id`

**Root Cause**: Race condition between initial state loading and WebSocket event handling

**Affected Files**:
- `src/hooks/useMesssages.js:167-168` - WebSocket event handling
- `src/hooks/useSessionFileUpload.js:32-53` - Session validation logic
- `src/components/ChatSession.jsx:235-242` - State initialization
- `src/components/InputArea.jsx:15, 39-44` - Processing state display

**Solution**:
1. **Fix State Synchronization** in `useMessages.js:167-168`:
   - Add additional logging to track when `assistant_upload_complete` events are received
   - Ensure the state update is properly propagated to all components

2. **Enhanced Session Validation** in `useSessionFileUpload.js:32-53`:
   - Add more robust state checks and ensure the `setFileProcessingState(false)` call is properly executed
   - Add a small delay to ensure state propagation

3. **Add State Recovery Logic** in `ChatSession.jsx:235-242`:
   - Force a state check after component mount when `fileUploaded` is true
   - Periodically validate processing state until it matches server status

## Bug 2: Multiple File Preview Issue
**Issue**: `InputArea.jsx` only shows single file preview instead of multiple files when multiple files are uploaded

**Root Cause**: The file preview UI in `InputArea.jsx` is hardcoded to show `fileInfo.filename` instead of using `fileInfo.files` array

**Affected Files**:
- `src/components/InputArea.jsx:102-139` - File preview display logic
- `src/hooks/useSessionFileUpload.js:126-130` - Multiple file data structure

**Working Reference**: 
- `src/components/FileInfo.jsx:68-102` - Already implements correct multiple file UI

**Solution**:
1. **Update InputArea.jsx file preview section (lines 102-139)**:
   - Replace single file display with logic similar to `FileInfo.jsx:68-102`
   - Show multiple file names with truncation (show first 2-3 files + "X more files")
   - Handle file removal for individual files vs. all files

2. **Enhance File Preview Handler**:
   - Update click handlers to support previewing individual files from the multiple file list
   - Add file selection interface if needed

## FilePreviewModal Analysis

### **Data Flow Traceback:**
1. `ChatSession.jsx` ← `fileInfo` from `useSessionFileUpload` hook  
2. `ChatInterface.jsx` ← `fileInfo` prop from ChatSession
3. `InputArea.jsx` ← `fileInfo` prop from ChatInterface
4. `FilePreviewModal` ← `fileInfo` prop from ChatInterface

### **Modal Design Issue:**
- ✅ **FilePreviewModal supports multiple sheets** (Excel multi-sheet files)
- ❌ **FilePreviewModal doesn't support multiple files** (multiple CSV/Excel files)
- The modal expects `fileInfo.sheets[]` but gets `fileInfo.files[]`

### **Current Modal Logic (FilePreviewModal.jsx:48-56):**
```javascript
const sheets = fileInfo.sheets || [{ 
  name: fileInfo.filename || 'Sheet1', 
  preview: fileInfo.preview,
  data: fileInfo.data,
  shape: fileInfo.shape,
  columns: fileInfo.columns
}]
```

### **✅ BETTER SOLUTION: Individual File Preview**

**Key Insight**: `FilePreviewModal` already works perfectly for single files! We should:
1. **Show multiple files** in `InputArea.jsx` 
2. **Pass individual file objects** to the modal when clicked
3. **Keep modal simple** - no need for complex multi-file handling

### **Individual File Structure from Backend:**
```javascript
// Each file in fileInfo.files[] has:
{
  'index': 0,
  'filename': 'file1.csv', 
  'assistant_upload_status': 'completed|pending|failed',
  // Missing: preview, data, shape, columns (needed for modal)
}
```

### **Implementation Options:**
**Option A**: Add individual file preview endpoint `/session/{id}/file/{index}/preview`
**Option B**: Backend includes preview data in all `fileInfo.files[]` objects

### **New Implementation Plan:**
1. **InputArea.jsx**: Show list of files with click handlers
2. **ChatInterface.jsx**: Handle individual file preview requests  
3. **FilePreviewModal**: Receives individual file object (no changes needed)
4. **Backend**: Add file preview data to individual file objects OR create preview endpoint
